## 1. Отмена запросов

- При каждом изменении поля поиска предыдущий запрос отменяется с помощью `AbortController`.
  - В `src/ui/main.ts` вызывается `searchController.cancel()` непосредственно в обработчике события `input`. Благодаря этому предыдущий запрос отменяется сразу при вводе нового символа, не дожидаясь окончания debounce.
  - В `src/core/searchController.ts` метод `cancel()` вызывает `abortController?.abort()`, чтобы отменить текущий запрос.
- Идентификатор запроса предотвращает обновление интерфейса устаревшими ответами.
  - В `src/core/searchController.ts` перед каждым запросом увеличивается `requestId`. После завершения запроса его идентификатор сравнивается с актуальным: `if (currentRequestId !== requestId) return;`.
  - Это дополнительная защита от ситуации, когда предыдущий запрос успел завершиться одновременно с отменой или его результат уже нельзя считать актуальным.
  - Одного флага отмены недостаточно: он не гарантирует, что уже завершившийся запрос или асинхронная операция не попытается обновить интерфейс. Поэтому используются и фактическая отмена запроса, и проверка его актуальности.
- `AbortSignal.timeout()` ограничивает время выполнения запроса.
  - В `src/core/searchCountries.ts` задано значение `DEFAULT_TIMEOUT = 10_000`, то есть 10 секунд.
  - Если сервер не отвечает в течение этого времени, запрос завершается с ошибкой таймаута.
- `AbortSignal.any()` объединяет ручную отмену и таймаут.
  - В `src/core/searchCountries.ts` создаётся общий сигнал: `AbortSignal.any([signal, timeoutSignal])`.
  - Благодаря этому запрос можно отменить как при изменении поискового запроса, так и при превышении времени ожидания.
- `AbortError` игнорируется, `TimeoutError` обрабатывается как ошибка.
  - В `src/core/searchController.ts` ошибка с именем `AbortError` не передаётся в обработчик отображения ошибки.
  - Ошибка таймаута не игнорируется и передаётся в `onError`, чтобы пользователь получил информацию о проблеме.

## 2. Задержка Debounce

- Для поиска используется задержка **500 мс**.
  - Значение задано константой `DEFAULT_DEBOUNCE_DELAY` в `src/ui/main.ts`.
- Это позволяет сократить количество лишних API-запросов во время ввода.
  - Например, при вводе названия страны `Germany` поиск не запускается после каждой введённой буквы. Запрос отправляется только после того, как пользователь перестал вводить текст на 500 мс.
- Отложенный вызов поиска должен отменяться при очистке поля ввода.
  - В `src/core/debounce.ts` реализован метод `debounced.cancel()`, который очищает установленный таймер через `clearTimeout`.
  - В `src/ui/main.ts` он вызывается, если после обработки значения поля `lastQuery` оказывается пустым. В этом случае вместо поиска отображается начальное сообщение с помощью `showStartMessage`.
- Если задержку сильно уменьшить — то будет сыпаться много запросов, если сильно увеличить — пользователю придется долго ждать начало поиска.
  - 500 мс — компромисс между отзывчивостью интерфейса и количеством обращений к API.

## 3. Сложность алгоритмов (Big O)

- **Маппинг:** \(O(n)\), где \(n\) — количество стран в ответе API. Каждая страна преобразуется один раз.
  - В `src/core/searchCountries.ts` используется `resolve.map(mapCountryResponse)`.
  - В `src/core/mapCountryResponse.ts` поля ответа API преобразуются в модель `Country`.
  - Дополнительно обрабатывается список валют через `countryResponse.currencies?.map(...)`. Если учитывать общее количество валют во всех странах как отдельную величину \(c\), сложность составляет \(O(n + c)\). При ограниченном количестве валют на страну это соответствует \(O(n)\).
- **Кэширование:** не реализовано.

## 4. Принципы Clean Code

- **Single Responsibility:** запросы к API, преобразование данных, отображение интерфейса и работа с модальным окном разделены на отдельные модули.
  - `src/core/searchCountries.ts` отвечает за получение данных от API и обработку HTTP-ответа.
  - `src/core/mapCountryResponse.ts` отвечает за преобразование ответа API в модель приложения.
  - `src/ui/main.ts` связывает поиск с пользовательским интерфейсом.
  - `src/ui/cardModal/cardModal.module.ts` отвечает за открытие, закрытие и анимацию модального окна.
- **Pure Functions:** `mapCountryResponse` преобразует данные API без побочных эффектов.
  - Функция принимает `CountryResponse` и возвращает новый объект `Country`, не изменяя исходные данные.
- **Encapsulation:** `HttpError` инкапсулирует информацию об HTTP-ошибках.
  - В `src/core/errors/httpError.ts` класс хранит HTTP-статус в свойстве `status` и задаёт собственное имя ошибки `HttpError`.
  - В `src/core/searchCountries.ts` этот класс используется для передачи информации об ошибках HTTP-ответов, отличных от `404`.
- **Reusability:** `createElement` централизует создание DOM-элементов.
  - Функция используется в разных UI-модулях, например в `src/ui/main.ts` и `src/ui/countryCard.ts`, что позволяет не дублировать логику создания и настройки элементов.
- **Type Safety:** интерфейсы TypeScript описывают ответы API и данные приложения.
  - В `src/core/types.ts` определены типы `CountryResponse` и `Country`, которые разделяют структуру исходных данных API и модель, используемую приложением.
  - Например, `searchCountries` принимает `AbortSignal` и возвращает `Promise<Country[]>`, а `mapCountryResponse` явно принимает `CountryResponse` и возвращает `Country`.
